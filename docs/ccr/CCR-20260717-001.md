# Change Control Record

**CCR ID:** CCR-20260717-001
**Version:** d9f20dd4afc48d04968a26a58486be6f3441a025

## Problem Description
Hardware configuration variables for the watchdog timeout and system latency were scattered, making it difficult to enforce the safety-critical invariant that the watchdog timeout must strictly exceed the maximum system latency at compile time.

## Proposed Change
Migrate hardware configuration safety assertions out of operational logic into a dedicated Verification module (`src/Safety/Verification.hs`). Expose a composite validation symbol (`assertSafetyChecks`) evaluated during main bootstrap to guarantee invariants at compile time.

## Impact on Hazards
Impacts Hazard ID H-SYS-015 and H-SYS-003.
This change directly mitigates H-SYS-015 by guaranteeing that an invalid hardware configuration where SystemLatency >= WatchdogTimeout will cause a compilation failure, ensuring the invariant is statically verified before runtime. It also reduces risks associated with Watchdog timer and Watchdog Timeouts by ensuring the bounds are statically safe.

## Quality Policy Origin
ISO 13485 Clause 7.3.3 Design and Development Outputs (must be suitable for verification against design inputs).

## Verification Strategy
Verified by GHC type checker at compile time. CI checks will run cabal build to verify compilation succeeds. A manual verification is performed by locally modifying `SystemLatencyMs` to be greater than `WatchdogTimeoutMs` and observing compilation failure with the specific Type Error.
