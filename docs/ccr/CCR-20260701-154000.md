# Change Control Record

**CCR ID:** CCR-20260701-154000
**Version:** HEAD

## Problem Description
The `Safety.Token` module was failing to compile because `fdRead` returns a String rather than a raw ByteString in modern GHC/unix environments, causing type mismatch when generating security tokens.

## Proposed Change
Updated `Safety.Token` to use the unencoded memory buffer function `fdReadBuf` from `System.Posix.IO`. Allocated a memory buffer using `allocaBytes` and safely copied the raw binary entropy into a proper `ByteString`.

## Impact on Hazards
Impacts **H-SYS-007**.
The change ensures that raw unencoded bytes are correctly read from `/dev/urandom` without implicit string conversions that could compromise the entropy or crash the program.

## Quality Policy Origin
ISO 13485 Clause 7.3.9 - Control of Design and Development Changes.

## Verification Strategy
Automated verification via compilation pass, unit tests, and the `compliance-checks` CI pipeline, specifically verifying memory allocation within the `generateToken` function.
