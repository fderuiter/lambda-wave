# Change Control Record

**CCR ID:** CCR-20260701-154000
**Version:** 0cf2b3f

## Problem Description
The `Safety.Token` module used `fdReadBuf` from `System.Posix.IO` to read entropy bytes from `/dev/urandom`. However, the implementation did not account for the POSIX-specified behaviour that `read`-family calls may return fewer bytes than requested (short read). As a result, the token could silently be generated from fewer than 16 bytes of entropy, reducing security margin. In the degenerate case of a 0-byte read, an empty token would be produced without error.

## Proposed Change
Updated `Safety.Token` to introduce a `readExact` helper that retries `fdReadBuf` in a loop until exactly 16 bytes have been accumulated. If the device returns fewer than 16 bytes (including a 0-byte read indicating EOF or error), the function raises a security violation rather than producing a token with reduced entropy.

## Impact on Hazards
Impacts **H-SYS-007**.
The change ensures that exactly 16 bytes of raw entropy are always consumed from `/dev/urandom` before encoding, preventing silent entropy reduction due to short reads.

## Quality Policy Origin
ISO 13485 Clause 7.3.9 - Control of Design and Development Changes.

## Verification Strategy
Automated verification via compilation pass, unit tests, and the `compliance-checks` CI pipeline, specifically verifying memory allocation within the `generateToken` function.
